# 实施顺序与验收

初始目标：先在一个指定测试群中让 Dot 按 `reserved2` 的方式参与聊天。首次接入不迁移 DSH 完整对话历史；需要的人设与群状态通过明确的读取接口提供。

- [ ] 将真实 QQBridge 或 Dot 联调结果加入验证记录。

本阶段的测试只能证明本地原型行为，不能证明外部协议兼容。

## 1. QQBridge 后端边界

在固定上游 commit 上实现按会话选择后端，隔离 DSH 会话创建、唤醒投递、运行开始/结束与授权策略。保留其他会话原来的 DSH 行为。

验收：同一测试会话不会同时启动 DSH 与 Dot；Dot 分支不依赖 DSH 在线；后端切换后拒绝旧运行迟到的发送与完成；原有暂停、白名单及限频仍生效。补丁应附固定基线和可重复应用步骤。

## 2. 持久化和桥接适配

落地会话归属、运行租约、读水位、发送幂等记录、观察计划与 outbox；为 QQBridge 提供受限适配接口。存储选择在明确单机部署方式后确定。

验收：进程重启不丢未确认消息；不确定发送不会自动重发；跨进程或重复请求不能产生两个有效运行；潜水观察不依赖一个持续数分钟的模型工具调用。

## 3. 远程 MCP 与 MCP Events

依据届时的官方文档实现服务发现、工具、事件目录、订阅/取消、回调验证和带签名的 webhook 投递。需要公开 HTTPS 端点或平台支持的 Secure MCP Tunnel，并在用户的 ChatGPT 中安装自定义插件。

验收：认证与会话授权隔离；订阅持久化；验证挑战通过；重复、乱序、过期事件有确定处理方式；平台接收事件成功时不会误标记运行已完成；租约在实际领取运行时开始。

## 4. 单群真实联调

至少覆盖以下场景并记录实际版本、日志摘要和结果：

| 场景 | 通过条件 |
| --- | --- |
| 正常回复 | 一次有效发送，随后显式收尾 |
| 选择沉默 | 零发送也正常完成，不进入异常重试 |
| 思考期间新消息 | 只确认已处理水位，新消息下一轮可见 |
| 事件重投 | 不产生重复业务运行或重复发言 |
| 发送超时 | 保留不确定状态，通过回执恢复 |
| Dot 失败或漏收尾 | 租约到期可恢复，旧请求不能破坏新运行 |
| 潜水与重新唤醒 | 观察门保留，满足触发条件后能够再次唤醒 |
| 切换回 DSH | 会话归属明确，旧 Dot 动作被拒绝 |
