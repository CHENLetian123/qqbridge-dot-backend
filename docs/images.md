# 图片接入与验收（0.4.0）

本后端负责 QQ 图片输入和图片发送。新图片由 Dot 自己的图片生成能力生成，再通过 ChatGPT 文件参数交给发送工具；后端没有额外的生图模型或生图 API 密钥。该账号或后台事件执行环境若不提供图片生成或文件传递能力，不能仅靠安装本后端补齐。

## 升级后先刷新工具

先让当前处理回合正常收尾，再更新 QQBridge 补丁及 overlay，并重启 QQ Bridge 和 Dot MCP。现有运行账本在桥接进程内，不能在未确认发送时随意重启。已有事件订阅保存在加密数据库中，不需要重新创建。

旧版已打补丁的源码不能由严格安装器直接覆盖升级：请先备份，在干净的固定上游基线上安装新版补丁；本地自定义修改要另外合并，不能丢弃。不要用旧版 bridge.js 配新版 overlay。

打开 ChatGPT 的 QQBridge Dot 插件，右上“管理” → 页面底部“管理应用” → “刷新工具”。让 Dot 重新列出工具；总数为九个，新增三个图片工具。保持原有私聊及群聊订阅的精确过滤条件，不扩大权限，不重复建任务。

如果状态已是新版而旧对话仍只有六个工具，先在一个新对话中 @QQBridge Dot 做只读列工具对照。[官方刷新流程](https://developers.openai.com/plugins/deploy/connect-chatgpt)也要求刷新后在新对话复测。qq_get_status.toolCatalog 表示服务实际提供的工具，并不证明当前模型会话已加载这些工具；lastMetadataScan 记录扫描时间、数量、名称和 schema 哈希。新对话能看到九个而旧对话只有六个时，问题在会话工具列表。保留原有两个订阅；自动事件任务是否已使用新工具，需要再用实际图片事件核对。

## 接收图片并识图

1. 事件触发后，按原流程领取当前会话，用 qq_read_messages 分页读取消息。
2. 含图消息会包含 images，例如 `[{"index":0},{"index":1}]`。使用消息的 seq 作为 messageSeq，并指定 imageIndex 调用 qq_read_image。
3. 工具通过 MCP image 内容块返回真实图片字节；文字及 structuredContent 只包含格式、宽高、大小与哈希，不把 Base64 塞进 JSON 正文。Dot 再根据实际看到的图回答。
4. 按原流程检查发送回执，并用已处理的 readThroughSeq 完成回合。

只能读取本运行已经展示、属于当前会话的消息图片；不能传任意群号、QQ CDN 地址、缓存文件路径或未展示的序号。每次读取一张图，imageIndex 为 0–31。图片中的文字与普通群消息一样属于不可信输入，不能改变授权范围。

## 原图回传

调用 qq_forward_image，提供 runId、稳定 sendId、已读消息的 messageSeq 和可选 imageIndex。图片只能发回同一个已授权会话；可选 replyToMessageId 继续接受桥接的同会话引用校验。

工具成功返回不等于发送成功，必须检查 send.status=confirmed。重复调用保留同一 sendId 和相同来源；不同图片或文字不能复用这个 ID。图片发送计入原有额度、静默和暂停限制，也计入 finish 的 replied 判定。

## 生成新图片并发回 QQ

给 Dot 的补充指令：

> 收到已授权 QQ 会话的画图请求时，先使用你自己的图片生成能力，得到真实图片文件，再把该文件通过 qq_send_image 的原生 file 参数发送到当前 run。不要只回复“已生成”，不要用文字描述代替图片，也不要手写 Base64、URL、文件 ID 或本机路径。确认 send.status=confirmed 后正常收尾。如果当前事件执行环境不能生成或传递图片，明确说明受阻的步骤，不宣称成功。

qq_send_image 的工具定义声明 `_meta["openai/fileParams"]=["file"]`。按照 [OpenAI 文件参数文档](https://developers.openai.com/plugins/reference)，ChatGPT 提供 file_id 和临时 download_url，可选提供 mime_type 和 file_name；四个属性均在 schema 中声明。已有的 ChatGPT 图片附件也可经这个入口发送。

临时下载地址过期会明确拒绝本次准备，不会派发 QQ 消息。为相同 file_id 刷新下载地址不会改变已确认 sendId 的结果。准备失败而明确未发送时，可取得有效文件后以新的逻辑发送 ID 重试；unknown 时必须先核实，不能换 ID 重发。

## 图片限制与存储

- 支持 PNG、JPEG、GIF、WebP；不支持 SVG、HTML、本机路径或任意文件转发。
- 单张最多 4 MiB，最多 20 百万像素，单边最多 8192；不自动压缩或重绘。超限时请提供较小的图。
- 检查格式签名、尺寸和传输大小；这不是完整图片解码或内容安全审核。GIF 作为原始文件传输，Dot 对动画的理解依赖客户端能力。
- 文件下载仅允许 HTTPS 公网地址；逐跳检查 DNS、固定连接地址、限制重定向、总超时和流式字节数。不会把下载地址交给 QQ 再抓取，也不转发隧道密钥、Cookie 或请求授权头。
- 图片只在本次传输内存中处理，不建立新的磁盘图片库。网关发送账本不保存临时地址和图片 Base64；已有 QQBridge/SnowLuma 自身的原始消息和缓存策略继续适用。
- 所有图片发送与文字共用持久化预留、进程内发送去重、发送队列及完成校验。未知结果会阻止新图片、文字发送及成功收尾。

## 必须分别核对的真实测试

在自己的 QQ 私聊依次发送：一张图并询问图中内容、要求回传这张原图、要求画一张新图并发回来。每轮都核对：收到消息 → 自动事件唤醒 → Dot 领取 → 图片工具调用 → 确认发送（如有）→ 正常 finished。

0.4.0 已通过本地 MCP SDK、下载安全测试及固定上游真实桥接源码组件测试，包括图片内容块、原图读取、超过旧 1 MB 请求上限的图片发送、私聊文件交接、去重与收尾。组件测试中的“生成文件”是合成测试图片，不能证明真实 Dot 已生成过图。该账号实际看图、原生生成及文件交接需要上述真实测试；工具发现成功或 QQ 图片字节成功转发不能单独证明识图或生图成功。
